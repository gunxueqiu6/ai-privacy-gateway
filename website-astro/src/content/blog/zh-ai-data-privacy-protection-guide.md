## 为什么你发给 AI 的数据正在裸奔

2024 年 Samsung 员工把芯片数据粘贴进 ChatGPT 后泄密的案例，把"AI 数据出境"从安全话题变成了董事会话题。到了 2026 年，情况没有变好：Cursor、Claude Code、GitHub Copilot 这类 AI 编程工具默认把代码片段发送给云端模型，而这些代码里通常混着数据库连接串、内部 API 名、客户身份证号。调查显示，超过 60% 的企业开发者承认在 AI 工具中粘贴过生产环境的敏感数据。

**你发出去的数据，AI 提供商默认会用于训练和日志留存。** 这不是怀疑论，而是 OpenAI、Anthropic 等厂商服务条款里的默认事实——除非你显式关闭训练开关，否则提示词与输出会进入模型迭代管线。对企业而言，这意味着：客户数据、员工信息、商业机密，每一条都会跨出内网。

现有缓解手段都有结构性缺陷：

- **提示词纪律**：靠人记住"别贴敏感数据"完全不可靠，30 个人的团队里只要有 1 次疏忽就前功尽弃。
- **本地模型**：把 LLM 搬到内网解决了出境问题，但小模型能力下降明显，且 GPU 成本高昂，中小团队难以承受。
- **什么都不做**：等于把合规风险交给运气。GDPR 第 32 条要求"适当的技术与组织措施"，口头约定不算数。

需要一个不改变用户体验、不牺牲模型能力、不依赖人的自觉的方案。**答案是：在客户端和 AI 提供商之间放一层自动脱敏的代理。**

## AI Privacy Gateway 是什么

AI Privacy Gateway 是一个开源的 PII 脱敏反向代理。它坐在你的应用、IDE 或浏览器与 LLM API 之间，拦截请求，检测其中的敏感实体，替换成占位符，把"干净"的文本转发给 AI 提供商；响应返回时，再把占位符还原成真实值。

技术栈由三部分组成：

- **Python/FastAPI**：网关主服务，负责 HTTP/SSE 代理、路由、控制台与配置管理。
- **Rust PyO3（AC 自动机）**：敏感实体检测引擎用 Rust 编写，通过 PyO3 嵌入 Python，单请求检测延迟低于 1 毫秒。
- **SQLite + AES-256-GCM**：占位符与原始值的加密映射保险库，默认完全本地存储。

配套交付 5 个官方 SDK（Python、JavaScript/TypeScript、Flutter、Android、iOS）以及 Chrome/Edge 浏览器扩展，Windows/macOS 提供一键安装器。

**核心设计原则：数据不出境，功能不降级。** 模型看到的是脱敏后的占位符，但你的应用仍然拿回完整答案——往返重建机制保证这一点。

## 核心能力拆解

### 14+ PII 实体检测，延迟低于 1 毫秒

网关内置 14+ 类敏感实体识别，覆盖中文与英文场景：姓名、身份证号、手机号、座机号、电子邮箱、居住地址、银行卡号、车牌号、护照号、企业税号、IP 地址、日期时间、坐标经纬度等。

检测引擎用 **Rust 实现的 AC 自动机（Aho-Corasick）** 做多模式匹配，通过 PyO3 嵌入 Python 运行时。AC 自动机把全部敏感模式预编译成一次状态机的多模式匹配，对 10KB 文本的单次扫描在 1 毫秒内完成，远快于逐个正则匹配。编号型实体（身份证、银行卡）辅以上下文正则与校验位判定，减少误报。

### SSE 流式感知脱敏

LLM 通过 SSE（Server-Sent Events）逐 token 返回内容。如果网关先缓存整个响应再脱敏，首字节延迟会从几十毫秒暴涨到数秒，打字机体验直接报废。

AI Privacy Gateway 对每个 SSE chunk 做**增量匹配**，能识别跨 chunk 分段返回的敏感片段（例如身份证号被拆成三个 token 返回），同时保证重建正确。这是大多数脱敏网关（包括 LLM Guard）不具备的能力，也是流式场景下的核心差异点。

### 往返重建：脱敏不丢功能

往返重建（round-trip reconstruction）解决"脱敏之后答案没法用"的痛点。流程分两步：

1. **请求侧**：`姓名「张三」→ 占位符 [NAME_1]`，原始值以 AES-256-GCM 加密后写入本地 SQLite vault，占位符与密文建立映射。
2. **响应侧**：LLM 返回内容里的 `[NAME_1]` 被查表解密还原为「张三」，应用拿到的仍是完整答案。

AI 提供商从头到尾只看到占位符，无法反推真实数据。vault 支持过期清理，防止密文无限累积。

### AES-256-GCM 加密保险库

占位符映射存储在本地 SQLite，每个记录用 **AES-256-GCM 认证加密**，带独立随机 nonce，防止重放与密文篡改。密钥支持环境变量注入或 KMS 集成。**敏感数据的明文只出现在你控制的进程里。**

### 哈希链审计日志

企业版提供哈希链（hash-chained）审计日志：每条日志含上一条的哈希，任何历史修改都会导致链条断裂。日志覆盖脱敏事件、占位符映射、访问请求与管理员操作，可直接用于 GDPR/PIPL/HIPAA 举证。

### 多上游负载均衡

网关支持把脱敏后的请求分发到多个 LLM 上游（OpenAI、Anthropic、DeepSeek 等），统一 API Key 管理与故障切换。对多云策略或按成本路由的团队，这是免费方案里少见的企业能力。

## 架构原理（文字版）

数据流可以用一条链路讲清楚，不需要图：

```
AI 客户端（Cursor/应用/SDK）
        │  原始文本
        ▼
FastAPI 网关入口 → 请求拦截
        │
        ▼
Rust AC 自动机检测器（<1ms 扫描 14+ 类实体）
        │  命中敏感值
        ▼
脱敏器：敏感值 → 占位符，密文写入 SQLite vault（AES-256-GCM）
        │  干净文本
        ▼
多上游负载均衡 → LLM API（OpenAI/Anthropic/DeepSeek）
        │  SSE 流式响应（含占位符）
        ▼
流式还原器：逐 chunk 增量匹配，占位符 → 原始值
        │
        ▼
AI 客户端收到完整、未脱敏的答案
```

关键设计点有三个：检测必须在转发前完成（否则敏感数据已出境）；还原必须在流式输出中增量完成（否则首字节延迟不可接受）；vault 必须本地加密（否则脱敏等于脱了个寂寞）。

## 30 秒部署：三条路径

### 路径一：Docker 一行命令

```bash
docker run -d \
  -p 8080:8080 \
  -e LLM_API_BASE=https://api.openai.com/v1 \
  -e VAULT_KEY=$(openssl rand -hex 32) \
  -v pgw-vault:/data \
  --name ai-privacy-gateway \
  ghcr.io/gunxueqiu6/ai-privacy-gateway:latest
```

然后在 Cursor、Claude Code 或任何支持自定义 base URL 的客户端里，把 API 地址改成 `http://localhost:8080`。完成。整个流程不超过 30 秒。

### 路径二：Python SDK 接入

已有代码的应用不需要改业务逻辑，只改客户端地址：

```python
from openai import OpenAI
from ai_privacy_gateway import PrivacyConfig

# 原：client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])
client = OpenAI(
    api_key=os.environ["OPENAI_API_KEY"],
    base_url="http://localhost:8080/v1",  # 指向网关
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "user", "content": "请帮我审核这份包含身份证号 110101199003074512 的订单"}
    ],
)
# 网关自动脱敏后转发，LLM 只看到占位符；返回时自动还原
```

同一模式适用于 JS/TS、Flutter、Android、iOS 四个 SDK。

### 路径三：Windows/macOS 一键安装器

官网提供 Windows 与 macOS 的一键安装包，双击安装、填入上游地址、启动，随后浏览器打开本地控制台查看检测与审计记录。非 Docker 环境的最快路径。

### 浏览器用户

Chrome/Edge 扩展安装后，网页内的 AI 对话自动走脱敏链路，适合个人用户和无法改代码的场景。

## 合规视角：GDPR / PIPL / HIPAA

- **GDPR 第 32 条**要求数据控制者实施"适当的技术与组织措施"。本地化部署 + 加密保险库 + 审计日志，构成可举证的缓解措施：个人数据不出境，传输给第三方 AI 提供商的是脱敏文本。
- **中国《个人信息保护法》(PIPL)**对个人信息出境设有严格条件。网关保证个人信息在出境前完成脱敏，且 mapping 存储在本地的加密 vault，为"最小必要"原则提供落地工具。
- **HIPAA** 场景（医疗 PHI）：AES-256-GCM 加密 + 哈希链审计 + 本地部署，覆盖安全规则中加密与审计追踪的要点。医疗 CIO 可以直接把网关作为 PHI 出境的最后一道闸门。

需要注意：网关是技术控制措施，不能替代法律层面的数据保护影响评估（DPIA）与合同条款。但它是少数真正把"出境前脱敏"变成一行命令的产品。

## 常见问题 FAQ

### 1. AI Privacy Gateway 会拖慢我的 AI 请求吗？

不会。检测引擎是 Rust AC 自动机，单请求延迟低于 1 毫秒；SSE 流式处理是增量的，不引入整响应缓存，首字节延迟几乎不增加。相比直连 API，额外开销在 1-2 毫秒量级。

### 2. 脱敏后 AI 的答案质量会下降吗？

往返重建机制保证：答案返回时占位符会被还原为真实值，你的应用拿到的是完整答案。唯一变化是 AI 提供商视角看到的是脱敏文本，对模型理解影响极小，因为占位符保留了语义角色（姓名、地址、号码）。

### 3. 支持哪些 AI 提供商？

OpenAI、Anthropic、DeepSeek 等所有 OpenAI 兼容 API 格式的上游均可接入。企业版支持多上游负载均衡与故障切换。

### 4. 数据会不会被第三方看到？

不会。只有脱敏后的占位符文本会发给 AI 提供商；原始 PII 与映射密文存储在本地 SQLite vault，密钥本地管理。默认数据不出境。

### 5. 需要安装 Rust 或编译吗？

不需要。官方提供预编译的 Docker 镜像、Windows/macOS 安装器与 pip/npm 安装包，Rust 引擎已编译进二进制，用户零编译。

### 6. 免费版商业使用有什么限制？

PolyForm Shield 许可证限制商业使用。非商业/内部研究/学习场景免费；需要商业授权、SLA、多上游负载均衡与哈希链审计的团队购买企业版（$199-999/月）。

### 7. 浏览器扩展和反代网关是什么关系？

扩展面向个人与网页 AI 对话场景，直接在浏览器内脱敏；反代网关面向服务端与 IDE 场景，处理所有 API 流量。两者独立工作，可同时使用。

### 8. 占位符格式是什么？会不会和业务冲突？

占位符采用 `[ENTITY_TYPE_ID]` 格式，如 `[NAME_1]`、`[ID_CARD_1]`，前缀由网关统一生成，冲突概率极低；SDK 提供自定义前缀选项。

### 9. 如何迁移现有 LLM 集成？

把 base URL 从服务商地址改为网关地址即可，SDK 用法不变。Python/JS/TS/Flutter/Android/iOS 均有对应示例。迁移后可在控制台验证脱敏是否生效。

### 10. 审计日志能用于合规审计吗？

能。企业版哈希链审计日志覆盖每次脱敏事件、占位符映射、访问请求与管理员操作，支持导出为合规报告（GDPR/PIPL/HIPAA）。社区版提供基础访问日志。

AI 数据隐私隔离不是一个"要不要做"的问题，而是一个"用什么做"的问题。提示词纪律不可靠，纯 SaaS 脱敏把问题从左手换到右手，本地大模型代价过高。**AI Privacy Gateway 用 30 秒部署、零代码改动、本地化加密存储，把"AI 数据不出境"变成基础设施能力。**
