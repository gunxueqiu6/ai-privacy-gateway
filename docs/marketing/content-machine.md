## 1. 输入源 (Input Sources)

每周一扫描以下 5 个源，提取 3-5 个候选选题。

### Source A: GitHub Issues

**扫描位置：** Privacy Gateway 仓库 + 竞品仓库的 Issues / Discussions

**工具：** `gh issue list --repo <owner>/<repo> --state open --limit 30`

**提取信号：**
- 高赞 feature request → 博客主题（"用户最想要的 X 功能"）
- 重复出现的 bug report → 科普主题（"为什么 X 问题频繁出现"）
- 用户困惑的配置问题 → 教程主题（"如何正确配置 X"）

**输出格式：** 每条记录 `<GitHub_Issue_URL> | <描述> | <👍 数> | <潜在角度>`

### Source B: 社区问答

**扫描位置：**
- Stack Overflow: `site:stackoverflow.com "ai data privacy" OR "training data" OR "data leakage"`
- V2EX: `site:v2ex.com/go/qianduan` + `site:v2ex.com/go/ai` 中的相关讨论
- Reddit: `r/MachineLearning` / `r/privacy` / `r/datascience`

**提取信号：**
- 高频问题（多人问同一个问题）→ 标准答案式文章
- 争议话题 → 观点文章
- 实操求助 → 手把手教程

### Source C: 竞品动态

**扫描列表：**

| 产品 | 关注点 |
|------|--------|
| Skyflow | 新功能发布、定价变更 |
| IronCore Labs | 文档更新、案例研究 |
| Gretel.ai | 合成数据能力 |
| Private AI | 法律合规内容 |
| 阿里云/腾讯云数据安全 | 中国市场策略 |
| AWS Clean Rooms | 企业客户定位 |

**工具：** `feedly` / `Inoreader` 订阅竞品官方博客 + Product Hunt RSS

**输出：** 竞品功能 vs Privacy Gateway 对比表草稿

### Source D: 行业新闻

**关注事件类型：**
- 数据泄露事件（谁漏了、影响多大、怎么发生的）
- 监管变化（GDPR 罚款案例、中国数据出境新规、美国 AI 行政令）
- 大公司 AI 政策变更（OpenAI 数据使用条款、Apple 隐私策略）

**工具：**
- Google News Alert: "data breach" + "AI privacy"
- Hacker News: `news.ycombinator.com` 首页相关帖
- 36Kr / 虎嗅 / InfoQ: 国内科技媒体

**角度转化：** 新闻事件 → "这对你意味着什么" 类评论文章

### Source E: 用户直连反馈

**来源：**
- 客服邮件 / 工单
- 销售 Call 记录
- Twitter / 微博提及
- 产品内 feedback widget

**处理流程：**
1. 每周收集原始反馈到 `docs/marketing/user-voices/` 目录
2. 归类：技术问题 / 功能请求 / 价格顾虑 / 竞品对比
3. 频率分析：同一个问题出现 3+ 次 → 值得写一篇文章

## 2. 每周工作流 (Weekly Workflow)

### 时间块分配

```
周一 上午   扫描 5 个输入源 → 提取候选选题
周一 下午   评分 → 选出本周最佳选题
周二 全天   生成完整文章 (1500-3000 字)
周三 全天   适配 5 个平台版本
周四 上午   发布 + 安排社交帖子
周五 上午   分析上周数据 → 调整下期方向
```

### 执行清单

#### 周一：选题

- [ ] 扫描 GitHub Issues（自己的 + 竞品），记录高赞需求
- [ ] 扫 Stack Overflow / V2EX / Reddit 相关问答，记录高频问题
- [ ] 扫竞品官博和 Product Hunt，记录新发布
- [ ] 扫行业新闻，记录重大事件
- [ ] 整理用户反馈（邮件/工单/客服）
- [ ] 汇总 5-10 候选选题到 `选题池.md`
- [ ] 对每个选题评分（见第 3 节评分矩阵）
- [ ] 确定本周最佳选题
- [ ] 输出：`本周选题: <标题> | 评分: <总分> | 角度: <切入点>`

#### 周二：生成长文

- [ ] 用 "Blog Article Generator" prompt 生成初稿
- [ ] 人工编辑：补充自己的观点、调整语气、加入产品链接
- [ ] 添加 2-3 张配图（截图 / 图表 / 流程图）
- [ ] SEO 检查：标题含核心关键词，前 100 字含关键词，H2/H3 合理分布
- [ ] 内部链接：链接到 Privacy Gateway 相关文档页
- [ ] CTA：文章末尾引导试用
- [ ] 输出：`draft/<slug>.md`

#### 周三：多平台适配

对同一篇文章，用 "Platform Adapter" prompt 生成 5 个版本：

| 平台 | 风格 | 字数 | 特点 |
|------|------|------|------|
| 掘金 | 技术教程风 | 2000-3000 | 代码示例多，结构清晰 |
| 知乎 | 深度分析风 | 1500-2500 | 开头有观点，论证严谨 |
| V2EX | 极简讨论风 | 500-800 | 只抛核心观点，引导讨论 |
| dev.to | 国际技术风 | 1500-2000 | 英文，偏实践，带代码 |
| Medium | 英文叙事风 | 1500-2500 | 英文，偏故事性，有个人视角 |

#### 周四：发布与推广

发布顺序：

```
09:00  掘金发布 + 加入对应标签
09:30  知乎发布 + 添加到相关话题
10:00  dev.to 发布 + 加入 tag
10:30  Medium 发布 + 加入 publication
11:00  V2EX 发布（注意不要广告感太重）
11:30  生成 5 条社交帖子（Twitter / LinkedIn / 微博）
        → 用 "Social Post Generator" prompt
        → 安排到接下来 5 天每天一条
16:00  邮件 Newsletter 发送（如果有邮件列表）
```

#### 周五：分析与调整

- [ ] 查看上周各篇文章的 Page Views、阅读完成率
- [ ] 查看各平台互动（评论 / 点赞 / 转发）
- [ ] 查看 Privacy Gateway 试用注册是否有对应 bump
- [ ] 记录到 `content-analytics.md` 做长期趋势
- [ ] 根据数据调整下周选题方向

## 3. 选题评分矩阵 (Topic Scoring Rubric)

每个候选选题从 4 个维度评分，每项 1-10 分，总分 40 分。

### 维度定义

#### A. 搜索量 (Search Volume)

| 分数 | 标准 | 如何判断 |
|------|------|----------|
| 8-10 | 月搜索 1000+ | Google Keyword Planner / Ahrefs 数据 |
| 5-7 | 月搜索 100-1000 | 手动搜，有 autocomplete 建议 |
| 2-4 | 月搜索 10-100 | 有搜索量但不大 |
| 1 | 几乎没人搜 | 没有搜索数据 |

**快速估算方法：** 在 Google 搜这个短语，看搜索结果顶部的 "About X results"——100万+ 算高量，10万-100万 中等，1万以下 低。

#### B. 竞争度 (Competition)

| 分数 | 标准 | 如何判断 |
|------|------|----------|
| 8-10 | 几乎没有同主题文章 | 搜一下，只有 1-2 篇且质量不高 |
| 5-7 | 有几篇但质量一般 | 有 3-5 篇，但写得浅或过期 |
| 2-4 | 很多同主题文章 | 搜索结果前 10 全被大站占满 |
| 1 | 红海竞争 | 搜索结果全是权威站点 |

**黄金区间：** A >= 5 且 B >= 6 — 有搜索量且竞争不激烈。

#### C. 产品相关性 (Product Relevance)

| 分数 | 标准 | 说明 |
|------|------|------|
| 8-10 | 自然引导到 Privacy Gateway | 读者看完会搜 "privacy gateway" |
| 5-7 | 可以提及，但不是核心 | 文章中能插一段产品介绍 |
| 2-4 | 只能放广告式提及 | 强行关联 |
| 1 | 和产品完全无关 | 纯粹蹭热点 |

#### D. 时效性 (Timeliness)

| 分数 | 标准 | 说明 |
|------|------|------|
| 8-10 | 本周热点 | 新闻刚出 48 小时内 |
| 5-7 | 本月趋势 | 话题在本月持续升温 |
| 2-4 | 常青内容 | 什么时候写都行，不紧急 |
| 1 | 过时话题 | 已经不是热点了 |

### 评分卡模板

```markdown
## 候选选题评分卡

**标题：** <文章标题>
**来源：** <A/B/C/D/E> — <具体链接>
**切入点：** <一句话说明角度>

| 维度 | 评分 | 理由 |
|------|------|------|
| A. 搜索量 | /10 | |
| B. 竞争度 | /10 | |
| C. 产品相关性 | /10 | |
| D. 时效性 | /10 | |
| **总分** | **/40** | |

**决策：** ☐ 本周执行 / ☐ 放入备选池 / ☐ 放弃
```

### 选题决策门

```
总分 ≥ 30  → 本周执行（最强信号）
总分 24-29 → 放入备选题池，下周如果没有更好的就选它
总分 < 24  → 放弃，不浪费生产时间
```

**特殊规则：** 时效性 = 10 的文章，即使总分 < 24 也可破格执行（抢热点价值大于一切）。

## 4. AI 提示词模板 (Reusable AI Prompt Templates)

### 4.1 Blog Article Generator

```markdown
## Role
你是 [产品名称] 的技术内容营销专家。你擅长将复杂的技术概念转化为开发者喜欢阅读的实战文章。

## Task
根据以下信息生成一篇 1500-3000 字的中文博客文章。

## Input

**选题标题：** {TOPIC}
**核心关键词：** {KEYWORDS}
**目标读者：** {TARGET_AUDIENCE}（例如：AI 应用开发者、CTO、数据工程师）
**文章角度：** {ANGLE}
**参考来源：** {SOURCES}
**产品关联点：** {PRODUCT_ANGLE}

## Output Requirements

1. **结构：** 开头（痛点引入）→ 正文（3-5 个小节）→ 结尾（总结 + CTA）
2. **SEO：** 标题含核心关键词；前 100 字出现 1 次；H2 包含长尾词
3. **可读性：** 每段 ≤ 5 行；有列表和粗体强调；技术术语首次出现时解释
4. **原创性：** 不要照搬参考来源；加入自己的观点和实战经验
5. **CTA：** 文章最后 50 字引导读者了解 {PRODUCT_NAME}

## Style Guide

- 语气：专业但不学术，像资深工程师在跟你聊天
- 避免：过度营销语气、空洞的形容词（"领先的"、"创新的"）
- 使用：具体数字、对比表格、代码示例、截图描述

## Format

输出 Markdown 格式，包含：
- 建议标题（3 个备选）
- Meta description（120 字以内）
- 正文（带 H2/H3 层级）
- 文章标签（5-8 个）
```

**使用时替换的变量：**

| 变量 | 说明 | 示例 |
|------|------|------|
| `{TOPIC}` | 选题标题 | "AI 训练数据隐私泄露风险与 6 种防护方案" |
| `{KEYWORDS}` | 核心关键词 | AI 数据隐私, 训练数据保护, 数据脱敏 |
| `{TARGET_AUDIENCE}` | 目标读者 | AI 应用开发者, CTO |
| `{ANGLE}` | 文章切入点 | 从最近的数据泄露事件切入 |
| `{SOURCES}` | 参考来源 | 相关文章链接或问题链接 |
| `{PRODUCT_ANGLE}` | 如何关联产品 | 在方案中列出 Privacy Gateway 作为推荐方案 |

### 4.2 Platform Adapter

```markdown
## Role
你是跨平台内容适配专家。你擅长将同一篇核心内容调整为不同平台的风格和字数要求，保持核心信息不变但表达方式完全贴合平台调性。

## Task
将以下源文章适配为 {TARGET_PLATFORM} 版本。

## Source Article

{ORIGINAL_ARTICLE}

## Target Platform Requirements

| 维度 | 要求 |
|------|------|
| 平台 | {TARGET_PLATFORM} |
| 目标字数 | {WORD_COUNT} 字 |
| 风格 | {STYLE_DESCRIPTION} |
| 特定要求 | {PLATFORM_SPECIFICS} |

## Platform Profiles

### 掘金
- 技术教程风，代码示例丰富
- 标题带数字和效果词："N 个方法"、"从零搭建"
- 开头直接说"这篇文章讲什么"，不要绕
- 读者喜欢对比和排名

### 知乎
- 深度分析风，开头要有观点输出
- 引用数据来源增加可信度
- 可以带一些个人经验
- 结尾引导讨论

### V2EX
- 极简风格，500-800 字就够了
- 只抛核心观点，不要长篇大论
- 语气像在社区发帖，不要像官方公告
- 引导回复讨论，不要硬推产品

### dev.to
- 英文写作，国际开发者风格
- 偏实践和代码，理论内容少写
- 可以使用 #hashtag
- 封面图需要英文

### Medium
- 英文写作，叙事风格
- 开头有一个 hook 句吸引注意
- 可以有个人故事和感悟
- 配图需要英文文案

## Output

直接输出适配后的完整文章，不需要额外说明。
```

## 6. 分发检查清单 (Distribution Checklist)

### Pre-Publish (发布前)

通用：
- [ ] 文章经过至少 1 次人工编辑，没有 AI 味太重
- [ ] 内链已添加（链接到 Privacy Gateway 文档页或之前的文章）
- [ ] CTA 已经加上（试用引导 / 邮件列表 / 关注）
- [ ] 封面图已就绪（建议使用 Canva 模板统一风格）
- [ ] URL slug 已设置（包含核心关键词，短且可读）
- [ ] Meta description 已写（120 字以内，含关键词）
- [ ] Open Graph 标签已设置（控制社交分享时的标题和图片）

各平台差异检查：

| 平台 | 额外检查 |
|------|----------|
| 掘金 | 标签添加了 3-5 个；代码块有语言标注 |
| 知乎 | 话题关联正确；开头有观点句 |
| V2EX | 标题不广告感；正文不超过 800 字 |
| dev.to | 封面图是英文；tags 全部小写 |
| Medium | 加入了合适的 publication；有 subtitle |

### Publish (发布时)

- [ ] 选定最佳发布时间（中国站：上午 9-10 点 / 国际站：下午 3-5 点 UTC）
- [ ] 发布后 30 分钟内关注评论，及时回复
- [ ] 在社交媒体同步发布短帖

### Post-Publish (发布后 24 小时)

- [ ] 回复所有评论（尽量在 2 小时内回复第一条评论）
- [ ] 在 Privacy Gateway 官网 "Blog" 栏目同步发布
- [ ] 将文章加入 Newsletter 素材库（下期发送）
- [ ] 在飞书/企业微信群转发
- [ ] 记录到 `content-log.md`

### Follow-Up (后续 7 天)

- [ ] 第 3 天：回复新增评论
- [ ] 第 7 天：收集数据（阅读量、互动量、引流数）
- [ ] 表现好（Top 20%）→ 考虑翻译成英文/中文版本多平台分发
- [ ] 表现差（Bottom 20%）→ 分析原因：选题问题？标题问题？分发时机问题？

### B. 每周一执行 SOP（快速启动版）

```
09:00    打开文档 → 打开选题池
09:05    开 5 个输入源 Tab → 快速扫一遍
09:20    整理候选到选题池 → 评分
09:40    确定本周选题 → 填入日历
09:45    打开 AI 写作 prompt → 填入变量 → 生成初稿
09:50    初稿 OK → 进入人工编辑
09:55    今天的 Done → 剩下的周二继续
```

> 核心哲学：**执行胜过完美。** 前 4 周重点在建立节奏，文章质量在前 4 周迭代提升，不要在第一天就追求完美文章。每周一雷打不动执行，4 周后你的内容资产从 0 积累到 4-5 篇高质量文章 + 20+ 条社交帖子。
